01 / The case for AMS

Less paperwork.
More presence.

Attendance should be a reliable academic signal — not a daily administrative chore. AMS replaces scattered sheets, static codes, and delayed visibility with one dependable system of record.

01

Manual overhead

Roll calls consume class time and leave room for transcription errors, duplicate entries, and missing records.

↗
02

Fragmented records

When students, courses, and sessions live in separate spreadsheets, the full attendance picture is always one export away.

↗
03

Delayed visibility

Students need timely feedback. Faculty need a live roster. Administrators need institution-wide trends — not end-of-term surprises.

↗

03 / Designed for the local network

One room.
One source of truth.

AMS is designed for institutions that want a dependable local deployment. The server hosts the application; connected devices use the same Wi-Fi or hotspot to participate.

01
Start the server

The institution launches AMS on a laptop or dedicated host.

02
Connect the room

Students and faculty join the same local Wi-Fi network.

03
Open a session

Faculty creates a class session and projects its rolling QR code.

04
Verify and report

AMS validates tokens, updates records, and makes reports available.

05 / From clone to classroom

Run AMS
where you need it.

Set up the application on a local machine, connect your database, and share the host’s private IP with devices on the same network.

QUICK STARTbash
# clone the stable branch
git clone -b roshan \
  https://github.com/jeedijoshua-art/ams.git
cd ams

# install and configure
npm install
cp .env.example .env

# migrate and seed PostgreSQL
npx prisma migrate dev --name init
npm run seed
npm run admin:bootstrap \
  -- --email=admin@institution.edu

# start for local-network access
npm run dev:lan
01
Prerequisites

Node.js 20.x or 24.x and PostgreSQL 16, local or Neon.

02
Environment

Copy .env.example and provide database and Auth.js values.

03
Share the room

Run npm run lan:ip, then open the shown private URL on connected devices.

Deployment note

The showcase is static, but AMS itself needs its configured PostgreSQL/Neon connection and authentication secrets to run.
